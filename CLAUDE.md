# CLAUDE.md — 532-groqdemo

Instructor- and agent-facing notes for this repo. Committed on purpose: any DSCI 532 instructor should be
able to port a lecture demo to Groq from this file alone. Canonical KB copy:
`~/mds/kb/projects/per-project/532-groqdemo/CLAUDE.md`. Published copy of the porting section:
<https://ilyamusabirov.github.io/532-groqdemo/porting.html>.

## Context (why this project exists)

**Job:** Give instructors a one-file, clonable querychat app on Groq (free tier, open-weight models) plus an
eval suite that turns the lecture's claims about `extra_instructions` and hallucinated stats into numbers.
**When:** DSCI 532 LLM lectures (lecture 5 querychat intro, lecture 8 models/providers and evals).
**Audience:** Co-instructors first; students may clone it later.
**Origin:** Extracted from `DSCI_532_vis-2_book/code/lecture05/app-07-querychat.py` on 2026-10-07.
**Related KB:** `~/mds/kb/projects/per-project/DSCI_532_vis-2_book/`

## Layout

- `app.py` — the demo. Stays one file; anything bigger belongs back in the book repo.
- `evals/` — inspect_ai suite. Pure scoring logic in `evals/checks.py` (unit-tested in `evals/tests/`),
  solver and scorers are thin inspect wrappers, `evals/README.md` explains the matrix and scorers.
- `evals/results/summary.md` — latest full-matrix results (committed); `evals/logs/` — raw logs (ignored).
- `docs/` — GitHub Pages site (index, porting guide, eval report). `docs/eval-report.md` is generated by
  `evals/run_matrix.sh` from the summary; do not hand-edit it.
- `pyproject.toml` + `uv.lock` — all dependencies, including the `evals` group (installed by default).


## Porting any 532 demo to Groq

All lecture code goes through chatlas (Python) or ellmer (R). Porting = swap the client, add the key.

### Which model

| use | model id | why |
|---|---|---|
| default for querychat and tool demos | `qwen/qwen3.8-27b` | best tool choice and SQL in our evals, zero Groq schema errors |
| second opinion | `qwen/qwen3.6-27b` | close second; some schema errors |
| cheap fast plain chat | `openai/gpt-oss-20b` | fine for chat; 40 schema errors with querychat in the eval run |
| avoid with querychat | `openai/gpt-oss-120b` | Groq rejects ~1 in 3 of its `querychat_query` calls |

Ids drift; list what the key can see:

```bash
uv run python -c "
from dotenv import load_dotenv; load_dotenv('.env'); import os, openai
c = openai.OpenAI(base_url='https://api.groq.com/openai/v1', api_key=os.environ['GROQ_API_KEY'])
print(*sorted(m.id for m in c.models.list().data), sep='\n')"
```

Not available on Groq under this key (2026-10-07): embeddings, vision. RAG demos keep their embedder and
move only generation; lecture 6 image/PDF structured-output demos cannot be ported as-is.

### The change, per pattern

```python
# .env
GROQ_API_KEY="gsk_..."

# ChatGithub(...) / ChatAnthropic() / ChatOpenAI()  ->
from chatlas import ChatGroq
client = ChatGroq(model="qwen/qwen3.8-27b")

# apps using ChatAuto() (532-dbdemo app-04 etc.): no code change, in .env:
CHATLAS_CHAT_PROVIDER_MODEL="groq/qwen/qwen3.8-27b"

# querychat
qc = querychat.QueryChat(df, "name", client=ChatGroq(model="qwen/qwen3.8-27b"), ...)

# R / ellmer
chat <- ellmer::chat_groq(model = "qwen/qwen3.8-27b")
```

`system_prompt`, `register_tool`, `.chat()`/`.stream()`, `ui.Chat`, `extra_instructions`, `data_description`
are unchanged.

### Rate limits

250k tokens/min **per model**. querychat's system prompt is ~4.5k tokens, so a class on one model will see
429s: spread students across the two Qwen models. Evals: models in parallel, configs serial,
`--max-samples 3`; the solver retries 429s with a fresh conversation.

### Known quirks (from the evals; see `evals/results/summary.md`)

1. Groq validates tool arguments strictly; querychat marks `collapsed` required but says it may be omitted.
   Error text: `Tool call validation failed ... missing properties: 'collapsed'`. Hits gpt-oss-120b hard,
   qwen3.8 never. Wrap `.chat()` in try/except in demos.
2. DuckDB string comparison is case-sensitive: `class = 'FIRST'` returns zero rows silently. List real values
   in `data_description`.
3. Qwen emits reasoning content; show only `ContentText` parts of the last turn (`evals/solver.py`).
4. "women" on Titanic is ambiguous (`sex='female'` 233 vs `who='woman'` 205). Say "female" in demos.
