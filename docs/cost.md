## Scenarios: 150 students building a querychat dashboard

Requests = user messages to querychat across the whole milestone (building, testing, demoing, TA grading).
Follow-up messages carry conversation history, so input grows: 1.3× applied.

## Will it even run? Rate limits per key

Free tier: 8,000 tokens/min, 200,000 tokens/day, 1000 requests/day.
Developer tier: 250,000 tokens/min per model, 1000 requests/min.

| model | tokens per request | free-tier requests/day | free-tier TPM ok? | dev-tier requests/min (one key) |
|---|---:|---:|---|---:|
| qwen/qwen3.8-27b | 13,294 | 15 | no: one request bursts past 8k | ~18 |
| qwen/qwen3.6-27b | 12,256 | 16 | no: one request bursts past 8k | ~20 |
| openai/gpt-oss-20b | 10,094 | 19 | no: one request bursts past 8k | ~24 |
| openai/gpt-oss-120b | 9,094 | 21 | no: one request bursts past 8k | ~27 |

A class of 150 on one developer key, all active in the same minute, needs ~150× one request's tokens per minute per model; split the class across models or across a few keys.
