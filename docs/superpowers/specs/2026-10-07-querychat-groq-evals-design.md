# querychat × Groq evals — design

Approved 2026-10-07 (approach A: real querychat stack inside inspect_ai tasks).

## Goal
Compare Groq-served open models on querychat behaviour over Titanic, under the
system-prompt customizations taught in DSCI 532 lecture 5 (`data_description`,
`extra_instructions` format-only, `extra_instructions` that forces `querychat_query`).
Output: per model × prompt-config × scorer table usable on a slide.

## Matrix
- Models: `qwen/qwen3.6-27b`, `qwen/qwen3.8-27b`, `openai/gpt-oss-20b`, `openai/gpt-oss-120b`
- Prompt configs: `baseline`, `datadesc`, `format`, `format_query`
- Datasets: `titanic` (seaborn), `crashes` (fake planet data from the lecture hallucination proof)
- Epochs: 3 (tool choice is stochastic)

## Samples
Generated by `build_dataset.py`; targets computed from the dataframe so they never go stale.
Families: filter (expects `querychat_update_dashboard`), question (expects `querychat_query`),
reset, semantic traps that only `data_description` resolves, out-of-scope (expects no tool),
crashes hallucination probes. Each intent has 3–5 phrasings (canonical, terse, typo, indirect, formal).

## Solver
Custom `@solver`: build `QueryChat(df, name, data_description, extra_instructions, client=ChatGroq(model))`,
get `qc.client(update_dashboard=cb, reset_dashboard=cb)`, run `chat.chat(input)`, record observed
tool calls + SQL + final text into the TaskState store.

## Scorers (deterministic first)
- `tool_choice`: observed tool set == expected set
- `sql_result`: run model SQL in DuckDB, compare count/scalar to target (rate tolerance 0.5 pt)
- `format_adherence`: emoji-labelled lines + suggestion span + "overall: 38.4%" anchor (format configs only)
- `number_honesty`: numbers in reply must match DuckDB truth; concrete numbers with no query call = fail
- LLM judge on the Insight sentence: optional, off by default

## Non-goals
UI (Playwright) tests; non-Groq providers; greeting (UI-only, never reaches the model).
